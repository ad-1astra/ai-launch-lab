AI Launch Lab: teacher guide

Based on "Building a Self-Hosted Multimodal AI Stack", Process Guide v1.0. Learners take one AI from a blank page to launch over 8 zones and 24 missions.

Running it in the room

  • Time: about 3 to 5 hours in total. Split it over sessions by zone. Progress saves in that browser, so learners should keep the same device and browser.
  • Devices: laptops or desktops are best, because real training uses the CPU. Fine-tuning takes roughly 2 to 6 minutes on a typical laptop. Phones work for most missions, but they train slowly.
  • Internet: needed to load the site the first time. After that it runs from the browser's cache only if the pages stay cached, so test this before class if your connection is unreliable. The optional real open models need a large download.
  • Sharing a device: add a player on the campus page. Each player gets their own AI.
  • Pairs: one learner drives, one reads the guide and predicts what will happen before each run. Swap at each zone.
  • Test Arena: Streak Run and Quiz Duel are in the Arena, with at least 10 questions per zone.

What is real, and what is simulated

Real, on the learner's deviceSimulated, labelled in amber
The 12 cleaning stages on real rows, MinHash and LSH, PII scrub, Cohen's kappa, WER, code execution, perceptual hashes. LoRA, DPO and GRPO with real gradients. Merge, quantisation and sealed-test scores. Gateway keys, rate limits and routing. Retrieval, face, browser speech. The release zip, offline app and Node server.GPU rental and prices. Fine-tuning Whisper (the WER curve is a model). Docker Compose assembly. Cluster load test (a queue model, using planning figures). Canary traffic numbers.

Be honest with learners about scale. The base has 722,176 parameters. A real 8B model has about 10,000 times more. Their AI is strong on what it trained on, and weak elsewhere. That honesty is the guide's own message: fine-tuning shapes behaviour, and it does not create frontier intelligence. To make a short browser run work, the game makes these choices and discloses them: adapters sit on the top 2 of 4 blocks; the learning rate is scaled by 15; a TF-IDF matcher finds the closest trained question; known questions run on the pure base (multi-LoRA routing); and emotion events come from small closed-choice heads.

Ask while they play

  • Why does a request with an image and /code go to vision? (Rule order.)
  • Why reject the leaderboard star? (Its licence is research only, and it needs 80 GB or more.)

  • Why seal before collecting? (It defines what data you need, and later rows can be checked against it.)

Zone 3: Data Refinery (Part 4)

MissionConceptWhat the learner does
The provenance gateLicences, consent, share-alikeAdmits 11 and rejects 4 of 15 sources (rival API, non-commercial, scraped, no consent)

Modality benchSpeech, code, vision, emotion checksUses real WER, code execution, perceptual hash and kappa
Pass the quality gatesManual review, data cardReads a real sample, writes known gaps, signs the card

Answers for the broken line

  • Order: extract, normalise, language ID, heuristics, exact dedupe, near-duplicates, quality, PII, safety, decontaminate, format, split.
  • Settings: symbol ratio about 0.6, near-duplicate 0.8, drop refusals, chat template, split by conversation.

Ask

  • Why did a stage remove half of one source? (Look at the samples. Sometimes the source is bad, and sometimes the filter is.)
  • Why does the PII stage also merge rows? (Scrubbing makes them identical.)

Zone 4: Agent Sandbox (Part 6.2)

MissionConceptWhat the learner does
Build the cageIsolation, allowlist, timeouts, confirmations, auditConfigures the harness until 8 test commands behave correctly
Record verified trajectoriesVerification, recovery examplesSolves 3 tasks in a real virtual shell. Only verified runs are kept.

Answers: isolation Docker or gVisor, a timeout, allowlist on, confirm on, audit on, network off. Task 1 fix: write calc.js function add(a, b) { return a + b; } function multiply(a, b) { return a * b; }

Nothing typed here touches the real computer. It is a virtual file system.

Zone 5: Training Hall (Parts 5, 6.1, 6.2, 7)

MissionConceptWhat the learner does
GPU and the overfit testHardware table, tiny overfit testPicks the cheapest fitting GPU, then fixes the template, mask and learning rate until 20 rows are memorised
The real LoRA fine-tuneSafe hyperparameters, replay, beat the baseTrains for real on the cleaned data. It must beat the base on the sealed test.
Fix the failuresRounds beat one big run; dev vs sealedReads failures, writes better answers, retrains with a regression check
Train the agentMulti-LoRA, SFT, GRPOSecond adapter on verified trajectories, then real rewards from the harness
Polish with DPOChosen vs rejectedJudges 8 pairs of the model's own answers, then trains on those choices

Answers: template with <|user|>, assistant tokens only, learning rate 2e-4; rank 16 to 64, alpha 2x rank, 1 to 3 epochs, batch 32 or more, replay 10 to 30 percent.

Ask

  • The loss fell, but the model failed the recall test. Why? (Wrong template: it learned a format you will not serve.)
  • What happens with no replay? (General scores can fall. Try it.)

After launch

  • My AI: chat with voice and face, the agent, vision, images, documents, API, and thumbs feedback. Corrections can retrain it into v1.1 for real.
  • Offline app: one HTML file from the release runs anywhere.
  • Real API: node server.js from the release gives an OpenAI-compatible endpoint on a real port.
  • Next step on a real GPU: the release has real-gpu/ scripts and the cleaned dataset. These scripts are generated and have not been run on a GPU, so review them with the class first.
